Customer Segmentation API

Send five numbers about a customer. Get back which of four segments they belong to.

Open API docs Check health

Request: POST /predict

{
  "age": 40,
  "annual_income_k": 61.0,
  "spending_score": 51,
  "purchase_frequency": 13,
  "avg_order_value": 74.0
}

Response

Segment 2: Mainstream Families

Distance to each segment's centre (shorter is closer)

  • Affluent Conservatives2.947
  • Premium Loyalists2.397
  • Mainstream Families0.062
  • Young Digital Spenders2.314

The four segments

0 · Affluent Conservatives

High income, low engagement. Older, high basket value but rarely shop.

1 · Premium Loyalists

High income, high engagement, frequent buyers with premium baskets.

2 · Mainstream Families

Middle income, moderate engagement. The core mass-market cohort.

3 · Young Digital Spenders

Young, lower income, high engagement. Frequent small-basket buyers.

Endpoints

MethodPathWhat it does
GET/healthHealth check
POST/predictSegment one customer
POST/predict/batchSegment 1–100 customers
GET/segmentsList the four segments
GET/model/infoModel details and training metrics
GET/docsInteractive Swagger UI

Invalid input (out-of-range values, missing or unknown fields) returns 422.

How it's built

Stack

  • Python 3.11, scikit-learn (StandardScaler + KMeans, k = 4)
  • FastAPI, Pydantic, uvicorn
  • Docker, Pytest (52 tests)
  • GitHub Actions, GHCR, Render

On every push to main

  • Install dependencies and run Pytest
  • Build the Docker image and smoke-test /health and /predict
  • Publish ghcr.io/kritee0301/customer-segmentation-api

Run it yourself

docker build -t customer-segmentation-api .
docker run -d --name seg-api -p 8000:8000 customer-segmentation-api
curl http://localhost:8000/health
